# Phase 3 — Validation Lab (the hero)

**Priority:** P0 · **Requirement:** 6 · **Depends on:** Phase 0 protocol, Phase 2 engine · **Runs in parallel with:** Phase 2

## Goal
Show honestly how well Baseline works, for whom, and where it fails, using a simulated cohort that is **not** generated by the detector's own model, plus pilot data from Phase 7.

## 3.1 Simulated cohort generator

**Population:** for example 10,000 synthetic users, split by language (Arabic, English), age band, education, digital familiarity, sex. Mix parameterized from the evidence register and labeled.

**Risk profile:** Lancet factors with prevalence from Weqaya (obesity, diabetes, hypertension), family history, APOE4 carrier status (parameterized, synthetic).

**Ground truth trajectories (deliberately richer than the detector):**
- Groups: stable, normal ageing drift, slow decline, accelerating decline, step drop, transient dip (illness, sleep), Ramadan shift.
- Decline probability linked to age and risk profile.
- Heavy-tailed session noise; noise higher with low digital familiarity and for older users.
- Person-specific practice effects with different shapes.
- Missing sessions more likely in people who are declining.
- Floor and ceiling effects; occasional assisted sessions.
- Informant reports generated from true function with error (parameterized from A-IQCODE and AD8 performance).
- Built-in **bias scenario:** a few items made harder for one language or education group, so the DIF check has something real to find.

**Clinical pathway model:** usual care (symptom-triggered, delay parameterized from the Al Ain distribution) versus Baseline-triggered (flag → gate → review → assessment). Labeled as a model.

## 3.2 Metrics (definitions fixed in the Phase 0 protocol)

| Metric | Definition | Source |
|---|---|---|
| Completion | % of scheduled sessions completed; % who finish the baseline burst; drop-out by week | Simulation and pilot |
| Test-retest reliability | ICC(2,1) between baseline-burst halves and between bursts in stable users; Bland-Altman limits | Simulation and pilot |
| Parallel-form equivalence | Mean difference between forms | Pilot |
| Change-detection sensitivity | % of true decliners reaching Review within a set window | Simulation |
| Specificity | % of truly stable users never reaching Review in a year | Simulation |
| Lead time | True change onset to Review flag | Simulation |
| False-referral burden | False Reviews per 1,000 users per year; positive predictive value; one-stage vs two-stage gate | Simulation |
| Time to assessment | Flag → clinician review (console); modeled onset → assessment, usual care vs Baseline | Console and model |
| Fairness | All of the above by segment; equal-opportunity gap (sensitivity difference) and false-flag-rate gap between groups | Simulation and pilot |
| DIF | Items flagged by Mantel-Haenszel or logistic-regression DIF | Simulation and pilot |

## 3.3 Analyses
1. **Threshold tuning:** sweep thresholds; plot sensitivity vs false referrals per 1,000; choose v1 using the rule written in the protocol (for example: maximize sensitivity with false referrals ≤ a set limit and fairness gaps ≤ a set margin).
2. **Gate comparison:** one-stage vs two-stage, showing fewer false referrals at the cost of some days of delay.
3. **Sensitivity analysis:** vary noise, prevalence, practice size and missingness; report metric ranges.
4. **Fairness audit:** every metric by segment; highlight where performance is worse and what we would do about it.
5. **Ablations:** without context adjustment, without practice modeling, without informant. Shows each layer's value.
6. **Failure report:** the scenarios where Baseline misses or over-flags. Shown openly.

## Results (protocol run, seed 20261120)
Command: `python -m baseline_lab.run` from `lab/` (about 43 minutes on 4 cores). 10,000 simulated people over two years, daily arm; 5,000 per sensitivity cohort; 1,000 bootstrap resamples. Outputs: `docs/validation-report.md`, `web/public/lab/results.json` (read by `/[lang]/lab`).

- **v1:** Watch z −2.5, two-stage gate, rapid-drop z −3.2. No setting met every constraint, so the pre-registered fallback (A3.2) picked the setting with the smallest worst fairness violation among those within the false-referral limit.
- **Met:** test-retest ICC 0.88 (baseline halves) and 0.94 (consecutive blocks); 12-month specificity 0.974 [0.971, 0.978]; 25.3 [23.0, 27.7] false referrals per 1,000 person-years; the two-stage gate cuts false referrals from 58.7 to 25.3 for a median of 12 extra days.
- **Not met:** fairness (sensitivity gap 0.12 across education groups against a 0.10 limit; false-referral ratio 1.47, just inside 1.5); DIF (all 6 planted items found, but 44–54% of fair items also flagged, far above the 5% limit, so the Mantel-Haenszel check is over-powered at this sample size).
- **Sensitivity is low:** 0.33 [0.29, 0.36] at 12 months, PPV 0.48. The failure analysis shows missed decliners are mostly slow changers with low completion (36%) and dropout (76%); with missingness switched off sensitivity rises to 0.60. Engagement, not the detector, is the main limit.
- **Time to assessment (model):** median 23.5 months under usual care against 13.1 months with Baseline; 45% versus 22% assessed within 12 months; median flag-to-review 14.5 days. This is a model comparison, not an observed outcome.
- **Honest framing for the pitch:** the Lab shows where Baseline is safe (few false referrals, reliable) and where it is not yet good enough (sensitivity, education fairness, item bias screening). These are exactly what the local pilot must measure.

## Acceptance criteria
- Generator and detector are different models (reviewed by a second team member).
- Every metric is reported by segment with an interval, not a single number.
- The report states its limits in the first paragraph.
- Results reproduce exactly from the seed.

## Out of scope
Claims about real-world clinical accuracy.
